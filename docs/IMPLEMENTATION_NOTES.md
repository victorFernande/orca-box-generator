# Implementation and verification notes — version 1.3.0

## Rugged replacement contract

Schema 2 introduces `rugged_lid_height` for independent base/lid shell heights and `rugged_model` to identify legacy personal presets. The new Rugged has only `base`, `lid`, `clip_left`, `clip_right`: snap-assembled spherical rear joints and latches attached to the lid. It does not support the previous loose-pin or captive export mode. `clamshell_pip` remains independent. Production reconstruction modules never read the supplied reference meshes. Current checks are recorded in [RUGGED_SNAPLOCK.md](RUGGED_SNAPLOCK.md); historical Rugged results below are superseded for this shape.

The shell and rear joints share explicit attachment boundaries. Each front ear uses two dimensional interval graphs with one common triangulation and a marked root cap. Assembly removes the root cap and joins the exposed loop to the shell panel; overlapping closed solids are not treated as a union. Decimal crease planes use the same final float32 coordinates on both sides of an attachment, preventing nearly coincident open seams. Independent field, topology, vertex-link and full-mesh intersection tests check the resulting surfaces.

The latch is extracted from its own analytic dimensional field, with guarded contractions of tiny edges and a measured surface-error limit. Prepared meshes preserve its complete V/T/N arrays to avoid repeating this expensive extraction on each standard-card selection. Changes to W/D/base height translate the same local fittings; joint diameters remain fixed. A new lid height or clearance may require fresh extraction and is not covered by the standard-selection latency target. Rendering and STL/3MF export use the same manufactured surfaces, with proper rigid rotations for the print orientation.

The approved Rugged bank has independent fixed V/T/N digests in the test fixture, bound to the geometry-source fingerprint and approved candidate commit. Fresh ARM/x86 latch extraction can select a different endpoint or midpoint for a nearly tied tiny-edge contraction. Its vertex comparison allows the existing 0.002 mm contraction bound; triangle indices/topology remain exact, and fresh normals, nondegeneracy, positive volume and analytic-field error are checked separately. This numerical check does not replace or relax the strict byte identity of distributed resources. The macOS ARM observation was 89 differing vertex coordinates out of 1,691,007, maximum 0.00094223 mm; runtime, packaged arrays and approved model were unchanged by the test correction.

## Architecture and parameter contract

Each installation is independent: Python 3.12+, NumPy, inline offline HTML/CSS/JavaScript and WebGL2. The source package and flattened PEP 723 file expose one `@orca.plugin` entry point registering a Page and Script/Dock capability. Infrastructure adapted from Orca Gear Studio retains its MIT notice. No runtime sibling-project dependency, telemetry, CDN or external modeller is required.

The JSON-compatible parameter boundary is `normalize_params()` plus `validate_params()`. Mesh APIs expose `MeshData`, `generate_box_mesh()`, `generate_fit_test_kit()` and `collect_target_meshes()`. `build_part_field()` exposes the analytic solid for independent membership/clearance checks. Eight styles and eight standard starting presets are available: `lip_snap`, `rugged_box`, `sliding_lid`, `screw_corner`, `open_bin`, `snap_latch`, `stackable_bin` and `clamshell_pip`.

All dimensions are millimetres. `width_x` and `depth_y` describe the external base body; `height_z` is the outside floor-to-rim height for ordinary styles; in `stackable_bin` it includes the indexing foot, and in `clamshell_pip` it is the equal external height of each half. They are not cavity dimensions or the complete assembled envelope. Hinges, catches and clips can project beyond the body. For `snap_latch`, the flat cap top is `height_z + fit_clearance + lid_height`; `lid_wall_height` defines its skirt depth below the cap, not walls above it. The independent clip envelope can extend further.

`fit_clearance` is a dimensional gap per side. Lip Snap `snap_retention` is separate radial bead interference; its entry profile is progressively chamfered. Storage `latch_retention`, clip width and clip thickness control a different mechanism and do not estimate release force. `open_bin` can create two capsule-shaped hand openings on either left/right or front/back faces; their dimensions and upper margin are independent controls. It has no lid. `snap_latch` uses a removable flat cap and two separately printed lever latches that mount to pivots on the base. Integral side pins snap into the base sockets. The levers rotate to release their hooks from lid tabs and remain on the base while the lid lifts.

## Articulated lever latch contract

The current `snap_latch` replaces the previous removable C-retainer design. It still prints four pieces: base, lid and left/right levers. `latch_pivot_diameter` (2.4–4.0 mm) controls the integral pin and socket geometry. The socket mouths permit pressure-fit assembly toward the base, with deliberate temporary flexure, and retain the pins afterward. Hub/socket shoulders provide axial capture. Lever width, thickness and hook retention remain separate controls; their nominal dimensions are not release-force settings.

`latch_geometry(params, part)` supplies the pivot, open angle and staged motion metadata. `latch_open_transform(vertices, params, part, angle)` is a pure positive-X rotation. The opening control first rotates both levers to 90 degrees over the first 35% of travel with the lid stationary, then lifts the lid while leaving the levers on the base. Closing reverses that sequence. Metadata is accepted with its mesh/parameter snapshot so a pending edit cannot change the pivot of an older surface.

The hook/catch contact lies on the closing side of the pivot, with a physical base stop. A separate angular cam creates the closed click. Only its specified temporary contact region is allowed to interfere; the closed state and released motion have clearance in the tested samples. An accessible grip patch remains clear of the base/catch. Flat hub/pin faces support the lever print pose; preserve that orientation and assess material/adhesion/bridges rather than inferring support-free manufacture.

The independent combined subset passed **17 tests in 92.129 seconds** with `-B -W error`: ten adapted functional tests plus seven new cases in `tests/test_snap_lever_mating.py`. It covers real hook retention, lid lift after release with both levers still attached, progressive cam entry, radial/axial pivot capture, pressure-fit mounting without whole-body obstruction, stop/grip geometry, actual print-layer material starts and corrected large-pin/thin-grip limits. The non-Snap functional helper/test ASTs remain unchanged from the earlier baseline.

Focused profile checks and actual-mesh checks found no proper crossings or coplanar area overlaps in the tested new Snap boundaries, including the large-pin/thin-grip counterexample. Shared boundaries and zero-area tangencies are excluded. This is a numerical, mechanism-specific check at its stated tolerances, not an exact global self-intersection proof for all styles/inputs.

The post-freeze isolated browser passed 12 layouts and 37 interactions. New checks inspect actual WebGL model transforms: closed, partially released, both levers released with lid still seated, later lid lift, and pivot stability after resizing. The redesigned Snap page was subsequently verified in a fresh Windows OrcaSlicer 2.5.1 session, including staged motion, 3MF/four STL files and four visually loaded Plater objects. The final rebuilt/restarted native dock also passed: staged release, pivot edit retaining 100% opening, PT Resources/Print instructions, 3MF export and four actual Plater objects. EN→PT now updates the three previously stale labels immediately without geometry regeneration. The final focused UI subset passed 28 cases (one localization, ten visual-template, eleven cache/local-edit and six articulated-case UI/bridge checks). The complete local run passed **136 tests in 574.594 seconds** with `-B -W error` and Chromium enabled, without failures, errors or skips. This includes the final localization and revised storage-export checks. ## Equal-depth captive case contract

`clamshell_pip` has two equal-depth halves and two captive hinges, without a separate axle or a front latch. Canonical geometry is closed: the base floor is at Z=0 and the lid outside floor at `2H + c`, with `H=height_z` and `c=fit_clearance`. The hinge axis is at `Y=depth_y/2 + hinge_separation`, `Z=H+c/2`. `clamshell_open_transform(vertices, params, angle)` is a pure rotation by negative angle around X; 180 degrees opens both bowls upward with both outside floors on Z=0.

`pip_clearance` (0.20–0.60 mm) is independent radial/axial clearance. Each hinge has two bored base knuckles, a central lid barrel, integral axle and retaining heads wider than the bore. All barrels and lid heads have integral wall/floor pedestals in the open print pose. Each canonical half is one connected closed shell, genus four/Euler characteristic minus six; the combined open assembly has two shells and Euler characteristic minus twelve. Internal joining faces are omitted rather than exporting intersecting solids as a substitute for union.

Only `base_and_lid` and `full_suite` export targets are supported. Export applies the open transform and combines the halves into one `MeshData` object, `clamshell_pip_assembly`, so bed packing uses one shared transform. `clamshell_print_bounds()` describes width `width_x`, depth `2*depth_y + 2*hinge_separation` and maximum Z `H + c/2 + outer_radius`. This hinge envelope is higher than a half's body. Posts, ports, dividers, gasket, generic kit and isolated-half exports are rejected; incompatible requested features are not silently dropped.

Eight independent tests in `tests/test_clamshell_mating.py` passed after the pedestal correction. They verify actual float32 topology, single-cycle vertex links, normal/field agreement, broad bed-supported floor area for each open half, equal depth, the pure transform, bidirectional sampled clearance at 83 poses from 0 to 180 degrees, real axial end-stop capture and exact open collection placement. Print-event checks slice actual triangles between vertex-Z events below the rim, identify separate filled contours and query same-half material just below each event. A supported split is allowed; a newly appearing suspended barrel/head island is rejected. A connected whole shell alone is insufficient for this check.

The axle still bridges between its central and head supports, approximately `knuckle_length + 2*pip_clearance`. That is geometric support evidence, not a slicing result or a guarantee of support-free printing, automatic hinge release, physical movement, fatigue life or load capacity. Inspect bridging/support placement without filling the functional clearances and print a test assembly.

## Stacking contract

`stackable_bin` is an original open-access body with a solid central guide foot and load-bearing shoulders. `height_z` includes `stack_foot_height` (1–5 mm); the body underside is at the foot height and the inside floor at foot height plus `floor_thickness`. `stack_clearance` (0.10–0.80 mm per side) is independent of `fit_clearance`. `front_access_width` and `front_access_drop` lower the central front while retaining the full-height side/rear rims. Only the base is exported.

`stacking_pose_z(lower, upper)` validates both designs and their mating family: equal `width_x`, `depth_y`, `corner_radius`, `wall_thickness`, `stack_foot_height` and `stack_clearance` within the implementation tolerance. Heights and front-access parameters may differ. It returns `lower.height_z - upper.stack_foot_height`. That places the upper body's shoulders on the lower U rim, with its guide entering the cavity. Combined height is `lower.height_z + upper.height_z - upper.stack_foot_height`. This describes the physical assembly, not a request to print an assembled stack.

Five independent tests in `tests/test_stackable_mating.py` passed. Actual mesh faces supply finite upward/downward contact patches on both sides and the rear, with the empty upper mesh's mass projection inside the contact triangle. Samples check both directions for penetration along the assembly pose, vertical insertion and within-clearance lateral offsets; further downward movement or excess lateral movement encounters the supporting/indexing surfaces. Different heights/front accesses and incompatible-family rejection are covered. Additional extreme-radius, foot-height and clearance mesh checks passed. This is geometric evidence without a load rating, friction model or arbitrary-content tipping guarantee.

The general idea was informed by [Techro3D's stackable storage containers](https://makerworld.com/en/models/2465290-stackable-storage-boxes-containers-by-techro3d). The parameterized surfaces and tests here are original; no source mesh or visual asset is reused, and no mating compatibility with the reference products is asserted.

## Surface construction and reuse

Simple Lip Snap shells, the three storage styles and the articulated case use connected contour surfaces. Rounded corners retain a chord-error budget; capsule handle tunnels, catch surfaces and extruded clip contours share their boundary vertices. The fast path is checked against the same analytic solid used for the general field model. An attached feature is not represented by an overlapping closed mesh inside the base.

Inputs outside that path use analytic signed fields for rounded boxes, cylinders, slabs, unions and differences. Features join before extraction. A conforming six-tetrahedron decomposition extracts the surface, with roots refined against the field. A translated lattice avoids exact iso-node ambiguity; curved interfaces and primitive height events receive refinement. Extruded height spans use coarse slabs where applicable.

In that general path, float32 degeneracies are addressed by collapsing only minimum edges of collinear triangles, with a 0.002 mm safeguard. Convex coplanar patches can be replaced by fans preserving their boundary; concave patches and holes retain conforming triangulation. Directed edge pairing, connectivity, volume and appropriate Euler characteristic are checked. Euler characteristic is not universally two: the open bin with two hand openings has genus two and Euler characteristic minus two.

The interface chord target is `min(fit_clearance/4, 0.04 mm)`. Field samples on actual float32 vertices and triangle interiors check the geometric approximation; this is separate from printer accuracy. The general grid budget rejects excessive inputs rather than allocating without a bound. Complex accessories can still be slower than simple contour shells; see [generation measurements](PERFORMANCE.md).

The controller retains validated canonical part meshes in a byte-bounded cache. `orient_mesh_for_print()` transforms copies, allowing preview and export to reuse the same surfaces. Encoded preview arrays are also cached. Identical in-flight requests share a computation, and stale preview requests are coalesced. These changes remove orientation-only regeneration without promising a fixed latency for every model or host.

## Functional verification

The earlier ten-case functional baseline passed with `-B -W error`; its Snap cases were subsequently replaced by the articulated-lever acceptance described above. They check separate Lip retention/clearance and an axial lead-in; absence of permanent closed Rugged clip overlap in the sampled configurations; a Sliding detent barrier; and the new storage mechanisms. The latter checks include actual connected float32 meshes, opposite directed edges, manifold vertex links, field/chord parity, hand openings with genus-two topology, neutral closed clip clearance, progressive clip entry, a temporary withdrawal barrier, vertical lid retention with clips installed, and lid removal after releasing them.

A watertight mesh alone does not establish an operative joint. Closed-state clearance is distinct from deliberately transient interference during snap insertion/removal. These checks sample geometric paths and solids; they do not model elastic deformation, contact force, friction, fatigue or print shrinkage. Physical fitting, material selection, insert compatibility, grip comfort, sealing and spring durability require printed trials.

The generic fit kit is unavailable for `open_bin`, `snap_latch`, `stackable_bin` and `clamshell_pip`. It uses a small Lip Snap pair, a bore and a tongue, so it is not a calibration surrogate for every mechanism. Test a smaller configuration of the actual storage parts while retaining thicknesses, clearances, clip dimensions and retention; uniformly scaling an exported mesh changes the fit too.

## Shared session and native transport

The page and dock share canonical geometry and private user presets, while language and theme remain viewing preferences. A worker owns its running state, preventing an older callback from clearing a newer worker flag. Presets use atomic file replacement in private storage. Native transport uses WM_COPYDATA on Windows, Cocoa main-queue file opening on macOS and the Linux session D-Bus instance service with unique-owner routing. Transport acknowledgement means request transmitted, not that loading or slicing completed. Export and host-preset updates run off the UI thread; automatic configuration does not modify installed printer/filament profiles.
